# Таймкоды из описания

У части роликов в описании VK уже стоят главы. Их пишет человек, и это другая нарезка, чем интервалы Whisper. Whisper режет по паузам речи. Описание режет по темам: «определение», «пример», «задача 18».

Парсер в `whisper_fpmi/timecodes.py` читает и короткие метки, и метки с часом.

| Как написано | Секунды | Что это |
|--------------|--------:|---------|
| `12:04 Короткая метка` | 724 | 12 минут 4 секунды |
| `65:21 Долгие минуты` | 3921 | 65 минут, если часов в записи нет |
| `00:42:20 Тема` | 2540 | поле часа есть, час равен нулю |
| `1:05:30 После часа` | 3930 | час, пять минут, тридцать секунд |
| `01:16:02 — Ещё` | 4562 | то же с ведущим нулём |
| `2:15:04 Второй час` | 8104 | два часа |
| `04:54:28 Тема` | 17668 | без четверти пять часов |

`1:05:30` не превращается в одну минуту и пять секунд: сначала проверяется форма с часом.

Строка берётся, если метка стоит в начале, после маркера списка или после слова «Таймкоды:». Строка `Длительность: 1:16:38` главой не считается. Несколько меток на одной строке тоже разбираются. HTML-переносы `<br>` из ответа VK превращаются в новые строки до разбора.

Лектор берётся из строк «Лектор:», «Семинарист:», «Преподаватель:», «Читает:». Если в описании есть и лектор, и семинарист, остаётся лектор. «Оператор» и «монтажёр» в эту колонку не попадают.

На последней сборке из описаний вынуто **10704** главы у **1039** лекций. У **9992** меток в записи есть поле часа. **2448** меток стоят на первом часе или позже.

Эти главы — проверочная выборка для [поиска](search.md): запрос по названию главы должен найти фрагмент той же лекции внутри этой главы.
