Когда у вас есть только Windows, ничего страшного. Когда есть несколько операционных систем на одном диске, вы уже начинаете понимать, что если у вас Windows стоит, то сделать красивое разбиение дополнительных файловых систем под Linux уже затруднительно.
Отдельно Boot, отдельно Var, отдельно Home, корень. Для GPT такого ограничения 264. И в чем особенность разделения GPT? Там есть отдельный тип файловых систем, обычный FAT32, который помечается под названием EFIBOOT и предназначен для загрузки некоторых дополнительных программ, в частности, некоторые программки.
В Linux есть тут еще такой файлик, во многих из них. В Boot есть некоторое ядро, то есть название ядра. Обратите внимание, что в сигнатуре первые буфки MZ, а дальше какое-то ругательство. То есть ядро зачем-то скомпоновано в формате Windows исполняемого файла. Зачем?
На самом деле никакой это не исполняемый файл для Windows. Если его скопировать в Windows, то он нифига не запустится, то есть выдаст сообщение об ошибке, хотя можно будет его открыть тем же Dependency Walker, там честно будет отображать, что это настоящий Windows файл, только для подсистемы под названием ELF, EFI.
Что это такое? Это некоторый программный интерфейс для небольших программ, которые можно хранить либо во флеш-памяти, например, на чипе, на материнке, там, где флеш-память, вместо BIOS, либо в дополнение к нему.
Что обычно идет в EFI Boot прошивках? Какие-то инструменты для настройки пока, то есть если у вас материнка, там, где можно мышкой двигать, красиво отображают всякие метрики, температура процессора, еще чего-нибудь, скорее всего, он сделан с поддержкой EFI.
И одна из главных программ, которая идет во флеш-память, это менеджер загрузки. Хотя в теории никто не мешает туда и ядро запихать, если оно в формате EFI. Так вот, что такое менеджер загрузки?
Это программка, которая смотрит на GPT-разделе типа FAT32, ищет там каталог EFI флеш-бут, ну и файлик в соответствующей архитектуре. Если находит, то может его загрузить. Если, конечно, диск указан в качестве приоритета для загрузочного.
Под Linux он обычно монтируется в некоторый вложенный под каталог boot EFI. И фактически, для того, чтобы сделать загрузчик, нужно просто сделать отдельный раздел с файлами FAT32 на разделе GPT, создать файлик по определенному пути и там его хранить.
И размер файла может там, ограничений особо нет. То есть, какой размер файла с кем мы сделали, такой и будет. Да, ну, поскольку это разрабатывали Intel совместно с Microsoft, то понятно, что формат файла тут Portable Executable, который .exe.
Ну, в чем его принципиальное отличие в лучшую сторону по сравнению с обычным способом загрузки. Здесь нам уже не приходится использовать механизм прерываний для того, чтобы использовать базовую функциональность BIOS.
То есть, у нас есть достаточно богатый API для доступа к дискам, для доступа, на самом деле, много к чему. В последней спецификации есть куча разных функций, в том числе криптографических.
И все это выполняется либо в защищенном для 3,5-битных, либо даже в длинном режиме процессов. То есть, никаких legacy API у нас тут уже не требуется поддерживать. Все это извращение с gate A20, адресное пространство, 640 килобайт, все.
