# Whisper_FPMI

Расшифровки лекций [лектория ФПМИ](https://vkvideo.ru/@lectorium_fpmi). В репозитории лежит **текст**, не видео.

Полный список уже сохранённых лекций, сгруппированный по курсам: **[CATALOG.md](CATALOG.md)**.
Сейчас в репозитории **2322** расшифровок; на канале VK больше двух тысяч видео — скрипт докачивает только те, которых ещё нет.

## Как устроены файлы

| Папка | Что внутри |
|-------|------------|
| `result/` | Сплошной текст лекции (`.txt`) |
| `download/` | Тот же текст с таймкодами Whisper (`*.mp4.txt`) |
| `whisper_fpmi/` | Актуальные скрипты |
| `legacy/` | Старый YouTube-пайплайн, **не использовать** |
| `videos/` | Временные скачанные ролики (в git не входят) |

Формат записи в каталоге:

`номер. тема` — [текст](result/C++-1-stdmap-stdlist.txt) · [таймкоды](download/C++-1-stdmap-stdlist.mp4.txt)

Старые расшифровки сделаны моделью Whisper `medium`. Новые пишутся **`large-v3`**.

## Новый пайплайн

С канала VK видео качается **в самом низком качестве, но со звуком**, пачками **не больше 3 ГиБ**.
Внутри пачки несколько лекций качаются сразу, у каждого ролика yt-dlp берёт несколько потоков на фрагменты HLS.
Потом Whisper `large-v3` расшифровывает пачку, исходники удаляются — и круг повторяется.

Во время `run` и `transcribe` в терминале три уровня прогресса: **текущее видео** (у каждого воркера своя полоска), **пачка 3 ГиБ** и **все оставшиеся лекции**. На каждой полоске видно, сколько уже прошло и сколько примерно осталось.

```powershell
python -m pip install -r requirements.txt
# нужен ffmpeg в PATH

python -m whisper_fpmi catalog              # пересобрать CATALOG.md
python -m whisper_fpmi list                 # список видео канала
python -m whisper_fpmi run                  # пачки по 3 ГиБ → расшифровка → удаление
python -m whisper_fpmi run --max-gb 3       # то же явно
python -m whisper_fpmi run --limit 1        # проверка на одном видео
python -m whisper_fpmi transcribe .\file.mp4 --title "Название лекции"
```

Полезные флаги `run`:

- `--max-gb 3` — сколько гигабайт держать в `videos/` за один круг
- `--download-workers 4` — сколько лекций качать одновременно
- `--fragment-threads 8` — HTTP-соединений на один ролик (или фрагментов HLS)
- `--model large-v3` — максимальное качество (по умолчанию)
- `--device cuda` или `--device cpu`
- `--cpu-workers 1` — один CPU-процесс рядом с GPU. `0` — только видеокарта
- `--cpu-threads 10` — ядер у этого CPU-процесса
- `--cpu-queue 10` — сколько видео отдать CPU. GPU свою пачку не ждёт, даже если CPU ещё считает
- `--gpu-workers 1` — параллельных расшифровок на GPU. `0` — только CPU
- `--cookies cookies.txt` — если VK просит логин
- `--keep-video` — не удалять скачанный файл (тогда цикл упрётся в лимит диска)
- `--no-skip-existing` — перешифровать даже если текст уже есть

Первый запуск скачает модель `large-v3` (несколько гигабайт). Уже лежащие в `result/` лекции скрипт пропускает.
